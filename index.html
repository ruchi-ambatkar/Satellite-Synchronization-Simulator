Race Condition

Observe what happens when the Satellite and Ground Station access shared data without synchronization.

Two lanes, one shared count

🛰 Satellite

1. Read count
2. Compute count + 1
3. Write count
⚡
CONFLICTboth read the same old value

🖥 Ground Station

1. Read count
2. Compute count − 1
3. Write count

Both threads access shared data at the same time without protection. The last write silently overwrites the first, so the result is inconsistent.

Without mutex: ⚠ race condition
With mutex: ✓ one at a time

sleep() is not synchronization — a delay only makes timing easier to see. Only a mutex or semaphore guarantees mutual exclusion.

Synchronization

A mutex and two semaphores keep the shared buffer safe.

🔒 Mutex

Protects the critical section. Only one thread may modify the buffer at a time.

🔓 UNLOCKED

⬜ Empty semaphore

Counts free slots. The satellite waits on it before producing.

5

🟦 Full semaphore

Counts ready packets. The ground station waits on it before consuming.

0

  1. wait(empty)
  2. wait(mutex)
  3. Add packet
  4. signal(mutex)

🖥 Ground station (consumer)

  1. wait(full)
  2. wait(mutex)
  3. Remove packet
  4. signal(mutex)
  5. signal(empty)
